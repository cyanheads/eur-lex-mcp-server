# 0.13.0 — 2026-09-25

## Added

- **ECLI identifiers** — `eurlex_lookup_celex` accepts `identifier_type: "ecli"` (detected under `auto` by a case-insensitive `ECLI:` prefix) and returns an optional `ecli`; `eurlex_get_cases` rows carry `ecli` where CELLAR records one. An ECLI several records share resolves to the primary record with the lowest CELEX ([#84](https://github.com/cyanheads/eur-lex-mcp-server/issues/84)).
- **`related_member_state`** on `national_transposition` rows of `eurlex_get_relations` and `eurlex://document/{celexNumber}/relations` — the ISO 3166-1 alpha-3 code read from the measure's sector-7 CELEX (`GBR` for the United Kingdom) ([#85](https://github.com/cyanheads/eur-lex-mcp-server/issues/85)).

## Changed

- **`invalid_case_number`** (`ValidationError`) on `eurlex_get_cases` — a `case_number` that holds a non-CELEX character without parsing, names more than one case (`C-131/12 and C-132/12`), or is a prefix-less number dated outside 1953–1988 now fails before any CELLAR call; these values previously returned `no_results`.
- **CELEX-keyed queries** in `eurlex_lookup_celex`, `eurlex_get_document`, `eurlex_get_relations`, and both `eurlex://document` resources bind `?work cdm:resource_legal_id_celex "…"^^xsd:string` instead of scanning with `FILTER(STR(…) = …)`; `eurlex_query_sparql`'s description recommends the typed form ([#92](https://github.com/cyanheads/eur-lex-mcp-server/issues/92)).
- **Dev dependencies** — `@socketsecurity/bun-security-scanner` ^1.1.2 → ^1.1.3, `@types/node` 26.6.1 → 26.6.2.

## Fixed

- **`eurlex_get_cases`' `case_number`** matches every primary record filed under a `C-`, `T-`, or `F-` number (judgments, orders, AG opinions), not just the judgment, and accepts the `Case C-97/23 P.` reference form, procedural suffixes, Unicode hyphens, and pre-1989 numbers (`26/62`); `celex_fragment` echoes the widened pattern, e.g. `2023C*0097` ([#81](https://github.com/cyanheads/eur-lex-mcp-server/issues/81)).
- **`eurlex_get_cases`' `court`** selects by the CELEX court letter (`C` or `T`), so records under type letters the filter never listed — General Court AG opinions (`TC`), Opinions of the Court (`CV`) — are reachable ([#91](https://github.com/cyanheads/eur-lex-mcp-server/issues/91)).
- **Nested `select` sections in `eurlex_get_document`** — an article selected alongside the chapter holding it rides once inside the chapter's slice instead of being emitted and charged against the cap twice; `selected_sections` still lists it ([#88](https://github.com/cyanheads/eur-lex-mcp-server/issues/88)).
- **Formex chapter and section headings** wrapped in `<HT>` formatting are detected in `format: "xml"`, so the outline and `select.chapters` match the HTML rendering ([#90](https://github.com/cyanheads/eur-lex-mcp-server/issues/90)).
- **Formex article scan** runs in linear time; a run of unclosed `<TI.ART>` openers cost quadratic time ([#94](https://github.com/cyanheads/eur-lex-mcp-server/issues/94)).
- **Case-law labels** — resource types `JUDG_EXTRACT`, `ORDER_EXTRACT`, `OPIN_JUR`, `DEC_NC`, `DEC_REVIEW`, `GARNISHEE_ORDER`, `THIRDPARTY_PROCEED`, `DATPRO` and the court authors `CJ`, `GCEU`, `CST`, `CFI` render by name ("Judgment (Extracts)", "Court of Justice") instead of their raw codes ([#93](https://github.com/cyanheads/eur-lex-mcp-server/issues/93), [#95](https://github.com/cyanheads/eur-lex-mcp-server/issues/95)).
