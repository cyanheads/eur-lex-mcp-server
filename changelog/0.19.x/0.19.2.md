# 0.19.2 — 2026-10-25

## Added

- **`eurlex_get_relations`** `relation_types` gains `adopts` and `adopted_by`, linking an act to the proposal it adopts and a work to the act that adopted it. An omitted `relation_types` now traverses fifteen types, as does `eurlex://document/{celexNumber}/relations`. ([#167](https://github.com/cyanheads/eur-lex-mcp-server/issues/167))
- **`eurlex_get_relations`** amendment, repeal, interpretation, and adoption rows carry `provisions`, and a new optional `article` input narrows `interpreted_by` to rulings with a recorded provision in that article. `article` with a `relation_types` list lacking `interpreted_by` fails as `article_not_applicable`. ([#168](https://github.com/cyanheads/eur-lex-mcp-server/issues/168))
- **`eurlex_get_document`** and `eurlex://document/{celexNumber}` return optional `eli`, `oj_reference` (its page range cites numeric pages only), `dates_of_effect`, and `transposition_deadlines`. ([#169](https://github.com/cyanheads/eur-lex-mcp-server/issues/169))
- **`eurlex_lookup_celex`** resolves an Official Journal reference (`OJ L 281, 23.11.1995, p. 31`, `OJ L, 2024/1689, 12.7.2024`) to the act it names; a first page starting several acts returns `found: false` naming each CELEX. ([#170](https://github.com/cyanheads/eur-lex-mcp-server/issues/170))
- **`eurlex_lookup_celex`** accepts an act citation followed by its parenthesized OJ reference (`Directive 95/46/EC (OJ L 281, 23.11.1995, p. 31)`). ([#171](https://github.com/cyanheads/eur-lex-mcp-server/issues/171))

## Changed

- **Every tool's `content[]`** escapes upstream and caller text, notices included, so a CommonMark parse reads back what `structuredContent` carries.
- **`SPARQL_QUERY_TIMEOUT_MS`** above 2147483647 now stops startup, naming the variable; it was accepted before, and under Node the timeout it set expired after 1 ms.
- **A call's CELLAR SPARQL queries share one time budget** instead of each getting the full timeout: `SPARQL_QUERY_TIMEOUT_MS`, or `eurlex_query_sparql`'s `timeout_hint` when larger. A query started after the budget is spent fails as `sparql_timeout` before it is sent, each attempt's timeout is cut to what remains, and a retry ladder the budget cuts short fails with its last attempt's own error.
