# 0.20.2 — 2026-11-09

## Added

- **`eurlex_get_relations` `related_sectors`** keeps only related works whose CELEX opens with a listed sector; a first page names the requested types with none in those sectors, and a call that traversed every type and found no CDM relations says so in the `notice` ([#191](https://github.com/cyanheads/eur-lex-mcp-server/issues/191)). `member_states` without sector `7` and `article` without `6` fail as `member_states_not_applicable` and `article_not_applicable`.
- **`inputAliases` on all seven tools**: `celex`, `max_chars`, `query`, `citation`, `reference`, `celexNumber`, and `celex_number` resolve to each tool's identifier, `limit`, or keyword input ([#194](https://github.com/cyanheads/eur-lex-mcp-server/issues/194)).
- **`eurlex_get_document` `language` takes three-letter codes, and `select` takes a string, a list, or a key variant** such as a singular or case-variant key; `eurlex_browse_subjects` `language` takes three-letter codes too ([#195](https://github.com/cyanheads/eur-lex-mcp-server/issues/195)).
- **`eurlex_get_document` and the two `eurlex://document/{celexNumber}` resources name the held CELEX** when a CELEX misses by one numbering convention (consolidated CELEX with no or an unmatched date, a `(nn)` suffix missing or extra, a number not zero-padded): `not_found` carries it in the message and `data.held_celex`, or `resolve: "current_consolidated"` serves it. `eurlex_lookup_celex` returns `found: false` with a `notice` naming it ([#196](https://github.com/cyanheads/eur-lex-mcp-server/issues/196)).
- **`eurlex_lookup_celex` names the acts a procedure produced** when the procedure has no initiating act ([#190](https://github.com/cyanheads/eur-lex-mcp-server/issues/190)).

## Changed

- **`resource_type` carries a label for all 206 resource types CELEX works carry**, and the dead `AG_OPI` and `REC_SOFT` entries are gone ([#192](https://github.com/cyanheads/eur-lex-mcp-server/issues/192)).
- **A lookup CELLAR leaves without a complete response for 20 s is re-sent once** inside the call's time budget; paged and raw queries keep one attempt ([#193](https://github.com/cyanheads/eur-lex-mcp-server/issues/193)).
- **`eurlex_get_relations` `empty_relation_types`** lists every requested type with no rows on the page, including when a filter matched none ([#191](https://github.com/cyanheads/eur-lex-mcp-server/issues/191)).
- **`eur-lex-guide` skill 1.1 → 1.2**, covering the held-CELEX misses, no-date placeholders, and amendment notice.
- **`@cyanheads/mcp-ts-core` 0.13.22**: an out-of-range numeric string reports its bound, HTTP error responses echo the JSON-RPC id, a failed resource read logs once, Bun ≥1.4.4 is required, and startup refuses Node <24 and a malformed `MCP_HTTP_ENDPOINT_PATH` or `MCP_PUBLIC_URL`.

## Fixed

- **`eurlex_get_cases` and `eurlex_search_documents` recoveries name only unset filters**: the `sparql_timeout` and `offset_past_window` hints no longer suggest dropping a filter the call did not set, the empty first-page notice names only the filters it set, and `eurlex_search_documents` no longer suggests removing its only filter (which failed `no_filters`) ([#186](https://github.com/cyanheads/eur-lex-mcp-server/issues/186)).
- **CELLAR's no-date values `1001-01-01` and `1002-02-02`** are left out of `dates_of_effect`, `transposition_deadlines`, and `end_of_validity`, so `entry_into_force` is the earliest real date ([#187](https://github.com/cyanheads/eur-lex-mcp-server/issues/187)).
- **`eurlex_get_document` `notice` names an amending act** that changed an article setting a listed date of effect, matching article locations that continue with a dot (`AR 123.3`) ([#188](https://github.com/cyanheads/eur-lex-mcp-server/issues/188)).
- **`eurlex_get_relations` `member_states_without_measures`** is narrowed by `member_states` ([#189](https://github.com/cyanheads/eur-lex-mcp-server/issues/189)).
