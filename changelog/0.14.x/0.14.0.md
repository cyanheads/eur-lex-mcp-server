# 0.14.0 — 2026-09-25

## Added

- **`notice` enrichment field** on `eurlex_search_documents`, `eurlex_get_cases`, `eurlex_browse_subjects`, and `eurlex_get_relations`: on an empty first page it names what matched nothing and how to broaden it, and on a capped page it names the next `offset` ([#112](https://github.com/cyanheads/eur-lex-mcp-server/issues/112)).

## Changed

- **Empty first pages are results** — the four paged tools return `total: 0`, `has_more: false` with a `notice` instead of throwing. Breaking: `no_results`, `no_concepts`, and `no_relations` are removed from `errors[]` ([#112](https://github.com/cyanheads/eur-lex-mcp-server/issues/112)).
- **`invalid_author_institution`** (`ValidationError`) replaces `no_results` for an `eurlex_search_documents` `author_institution` with no letters or digits; a well-formed author that matches no institution is an empty page ([#112](https://github.com/cyanheads/eur-lex-mcp-server/issues/112)).
- **Keyword CELEX matching by shape** in `eurlex_search_documents` and `eurlex_get_cases`. Breaking: a digit-free keyword matches titles only, not CELEX substrings; a whole-CELEX keyword matches that CELEX, its `(01)`–`(20)` and `R(01)`–`R(20)` siblings (and `_INF`/`_RES`/`_SUM`/`_EXT` records), and its corrigenda, instead of every CELEX containing it. A partial CELEX keeps the substring scan ([#105](https://github.com/cyanheads/eur-lex-mcp-server/issues/105)).
- **`invalid_keyword`** (`ValidationError`) on both search tools for a `keyword` with no letters or digits, which previously ran a CELEX substring scan ([#105](https://github.com/cyanheads/eur-lex-mcp-server/issues/105)).

## Fixed

- **Date-bounded `eurlex_search_documents`** pages the CELEX keys before aggregating, as `eurlex_get_cases` does; searches that passed the 55 s client timeout, even for a single day, return identical rows in 0.6–1.6 s (a lone `date_from` 110 s → 0.6 s, `REG` + half-month 13.8 s → 1.4 s) ([#105](https://github.com/cyanheads/eur-lex-mcp-server/issues/105)).
- **Keyword searches** no longer scan every CELEX literal for a whole-CELEX or digit-free keyword: `32016R0679` went from 29 s to 0.5 s, and `privacy` from 43 s to 0.7 s with identical rows ([#105](https://github.com/cyanheads/eur-lex-mcp-server/issues/105)).
- **Cancelled calls** — `CellarSparqlService.query` aborts the in-flight SPARQL request on the caller's cancellation and rethrows the abort as itself rather than as `sparql_timeout`. The response body is read under the same classification, so a client timeout that fires mid-body fails once as `sparql_timeout` instead of being retried ([#122](https://github.com/cyanheads/eur-lex-mcp-server/issues/122)).
- **Echoed input** in notices and validation messages is bounded to 100 characters plus an ellipsis; `query_echo` keeps the whole value ([#112](https://github.com/cyanheads/eur-lex-mcp-server/issues/112)).
