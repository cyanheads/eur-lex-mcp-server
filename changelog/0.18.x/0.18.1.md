# 0.18.1 — 2026-09-26

## Changed

- **`eurovoc_concept` in `eurlex_search_documents`** requires the `http://eurovoc.europa.eu/` namespace. Any other URI (an ELI, a CELLAR work, another authority concept, a lookalike host) fails validation with a message naming the namespace, where it used to return an empty page.

## Fixed

- **`https://eurovoc.europa.eu/…` and upper-case scheme or host forms of `eurovoc_concept`** are rewritten to the `http://eurovoc.europa.eu/…` form CELLAR binds, so they return results instead of an empty page. `query_echo.eurovoc_concept` reports the http form.

## Security

- **`isSafeSparqlIri` rejects the whole IRIREF exclusion set** — U+0000–U+0020 and `` <>"{}|^`\ `` — plus any other Unicode whitespace ([#140](https://github.com/cyanheads/eur-lex-mcp-server/issues/140)). `work_uri` on `eurlex_get_document` and `eurlex_get_relations` and `eurovoc_concept` now fail validation on these characters instead of leaking CELLAR's SP030 error with the internal query attached; the refine messages name every rejected character.
- **`tests/sparql-lexical-safety.test.ts`** sends hostile values to every tool and resource string input and fails when a caller value lands outside a well-formed literal, IRI, or `bif:contains` phrase ([#64](https://github.com/cyanheads/eur-lex-mcp-server/issues/64)). It runs in `bun run test`; a new string input must be covered or explicitly exempted.
