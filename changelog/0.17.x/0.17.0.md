# 0.17.0 — 2026-09-25

Three changes are breaking for callers that depend on the old behavior:

- An `eurlex_query_sparql` ASK, CONSTRUCT, or DESCRIBE query now fails as `unsupported_query_form`, not `not_read_only`. Branch on the new reason, or rewrite the query as SELECT.
- `eurlex_browse_subjects` no longer returns concepts in alphabetical order. Rely on the tiers instead; `offset` pages stay stable.
- A `keyword` fragment that opens mid-year or mid-number (`016R0679`, `0679`, `0679R`) now matches titles only. Start the fragment at the sector and year (`02016R0679`), at the year and type letters (`2016R0679`), or at the type letters followed by the number (`R0679`).

## Added

- **OJ citations in `eurlex_lookup_celex`.** Under `identifier_type: "auto"`, a citation that names its act type and year resolves to its CELEX: `Regulation (EU) 2016/679` → `32016R0679`, `Directive 95/46/EC` → `31995L0046`, `Council Framework Decision 2002/584/JHA` → `32002F0584`. `No` before the numbers means number/year, and a two-digit year is 19YY. A citation without its act type (`95/46/EC`) or year (`Regulation No 17`) is not parsed ([#114](https://github.com/cyanheads/eur-lex-mcp-server/issues/114)).
- **`notice` on an `eurlex_lookup_celex` miss.** `found: false` now comes with a notice naming the CELEX, ELI, or ECLI tried, the CELEX pattern, and `eurlex_search_documents` ([#114](https://github.com/cyanheads/eur-lex-mcp-server/issues/114)).
- **`notice` on a zero-row `eurlex_query_sparql` result** whose query has an untyped string literal as a triple object. It says to type the literal (`^^xsd:string`, or `^^xsd:anyURI` for an ELI) or language-tag it. The query is still sent unchanged ([#115](https://github.com/cyanheads/eur-lex-mcp-server/issues/115)).

## Changed

- **`unsupported_query_form`** (`ValidationError`) in `eurlex_query_sparql` covers ASK, CONSTRUCT, DESCRIBE, an unrecognized keyword, and a prologue with no query. `not_read_only` now covers the ten SPARQL Update keywords only. Breaking: the same input returns a different reason ([#115](https://github.com/cyanheads/eur-lex-mcp-server/issues/115)).
- **`eurlex_browse_subjects` ranks matches in tiers**: an exact label first, then a label or word starting with the keyword, then any other substring, ordered by preferred label within each tier. `"AI"` now leads with artificial intelligence. `matched_label` reports the best-tier alternative label ([#113](https://github.com/cyanheads/eur-lex-mcp-server/issues/113)).
- **`ambiguous_identifier` recovery** in `eurlex_lookup_celex` lists the accepted forms, citations included, and points to `eurlex_search_documents` instead of `identifier_type` ([#114](https://github.com/cyanheads/eur-lex-mcp-server/issues/114)).

## Fixed

- **Partial-CELEX `keyword`** on `eurlex_search_documents` and `eurlex_get_cases` is answered from the CELEX full-text index, with a confirming substring test, and returns the same rows. `R0679` answers in 0.6 s where it used to time out, and a `date_from` search on `2016R0679` takes 0.5 s instead of 52 s. A fragment whose opening letters are not followed by a digit (`R(01)`) still scans every CELEX ([#123](https://github.com/cyanheads/eur-lex-mcp-server/issues/123)).
- **`eurlex_get_cases` `case_number` fallback.** A CELEX-character value that parses as no case number takes the same index route when it opens with the sector and year, the year and both letters, or both letters and the number. `2013CJ0131` takes 0.3 s instead of 14.3 s. Other values keep the scan ([#134](https://github.com/cyanheads/eur-lex-mcp-server/issues/134)).
- **Underscores in `eurlex_query_sparql` table cells.** An underscore between two letters or digits is no longer escaped (`72022L2555ROU_202405184`) ([#115](https://github.com/cyanheads/eur-lex-mcp-server/issues/115)).
- **Echoed identifiers** in `eurlex_lookup_celex`'s `ambiguous_identifier` message and `eurlex_get_relations`' `not_found` message are capped at 100 characters plus an ellipsis ([#135](https://github.com/cyanheads/eur-lex-mcp-server/issues/135)).
